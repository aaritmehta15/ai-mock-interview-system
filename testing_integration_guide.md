## Level 2 — Groq Integration (Real AI)

> Requires a Groq API key. Get one free at [console.groq.com](https://console.groq.com)


## Level 3 — Firebase Integration

> Requires a Firebase project. Follow these steps exactly.

### 3.1 Create Firebase project

1. Go to [console.firebase.google.com](https://console.firebase.google.com)
2. Click **Add project** → give it a name → disable Google Analytics → **Create project**

### 3.2 Enable Firestore

1. In your project → **Build** → **Firestore Database**
2. Click **Create database** → choose **Start in test mode** → **Next**
3. Select a region → **Enable**

### 3.3 Get service account credentials

1. **Project Settings** (gear icon) → **Service Accounts** tab
2. Click **Generate new private key** → **Generate key**
3. A JSON file downloads — rename it to `firebase_credentials.json`
4. Move it into your `backend/` folder

### 3.4 Update `.env`

```env
FIREBASE_CREDENTIALS_FILE=firebase_credentials.json
FIREBASE_PROJECT_ID=your-project-id   # from Project Settings → General
```

Restart server. You'll see:

```
INFO | firebase_service | Firebase Firestore initialised (project=your-project-id).
```

Now all `/log-study`, `/profile/*`, and `/plan/*` calls persist to real Firestore.

**Verify in Firebase console:**
After calling `POST /log-study`, open Firestore → you should see:

```
users/
  test_student/
    study_logs/
      2026-04-12/
        { user_id, date, hours_studied }
    plans/
      2026-04-12/
        { plan: {...} }
```

## Level 4 — Real Gmail (Firebase Auth Token)

> Requires: Firebase Auth on the frontend + Gmail scope added to Google Sign-In.

### 4.1 Enable Gmail API in Google Cloud

1. Go to [console.cloud.google.com](https://console.cloud.google.com)
2. **Select the same project** your Firebase is using
3. Search for **Gmail API** → **Enable**

### 4.2 Frontend — request Gmail scope during sign-in

In your React/TS frontend (wherever you do Google Sign-In):

```typescript
import {
  GoogleAuthProvider,
  signInWithPopup,
  getAuth
} from "firebase/auth";

const auth = getAuth();
const provider = new GoogleAuthProvider();

// ← THIS LINE IS CRITICAL
provider.addScope("https://www.googleapis.com/auth/gmail.readonly");

const result = await signInWithPopup(auth, provider);
const credential = GoogleAuthProvider.credentialFromResult(result);
const googleAccessToken = credential?.accessToken; // ← send this to backend

// Store it somewhere (localStorage, context, etc.)
localStorage.setItem("googleAccessToken", googleAccessToken ?? "");
```

### 4.3 Frontend — send token on every API call

```typescript
const accessToken = localStorage.getItem("googleAccessToken");
const userId = auth.currentUser?.uid;

const response = await fetch(
  `http://localhost:8000/generate-plan?user_id=${userId}`,
  {
    headers: {
      "Authorization": `Bearer ${accessToken}`
    }
  }
);
const data = await response.json();
```

### 4.4 Verify it's using real Gmail

In the backend terminal you'll see:

```
INFO | gmail_service | Gmail returned 12 message IDs.
INFO | gmail_service | Successfully fetched 12 emails from Gmail.
```

Instead of:

```
WARNING | gmail_service | No valid Google access token — using MOCK email corpus.
```

### 4.5 Test with Postman

1. Get the `accessToken` from your browser's dev console after sign-in:
   ```js
   localStorage.getItem("googleAccessToken")
   ```
2. In Postman → `GET http://localhost:8000/generate-plan?user_id=YOUR_UID`
3. Headers tab → `Authorization: Bearer <paste token here>`
4. Send → you should see real emails extracted

Use this checklist to verify priority scores are correct:

- `no_study_bonus` must be **absent** (student studied) ✓

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `warning: "Groq API unavailable"` in plan | No/bad `GROQ_API_KEY` | Set key in `.env`, restart server |
| `company_profile.source: "heuristic"` | Groq key missing or 429 rate limit | Set key or wait and retry |
| `"using MOCK email corpus"` in logs | No Bearer token sent | Add `Authorization: Bearer <token>` header |
| Gmail returns 403 | `gmail.readonly` scope not added in frontend | Add `provider.addScope(...)` before popup |
| Gmail token expired | Google tokens expire after 1 hour | Re-sign in on frontend, get fresh token |
| Firestore `using in-memory fallback` | `firebase_credentials.json` missing | Download from Firebase console → place in `backend/` |
| `404` on `/profile/{user_id}` | Profile not created yet | Call `POST /profile/{user_id}` first |
| `SyntaxError` on startup | Wrong Python version | Use Python ≥ 3.10 |

## 9. What Each Credential Does

| Credential | Required for | Without it |
|------------|--------------|-----------|
| `GROQ_API_KEY` | AI event extraction, company tier classification, daily plan | Heuristic company tiers, deterministic fallback plan |
| `firebase_credentials.json` | Persisting events/plans/profiles to Firestore | In-memory store (resets on server restart) |
| `Authorization: Bearer <token>` header | Reading real Gmail emails | Dynamic mock email corpus used instead |

> The system is designed to degrade gracefully at each level.  
> You can test all scoring and plan logic without any credentials at all.
